# Self-Service Kiosk

A self-service ordering kiosk for Windows. It is built from two parts that are
developed, released and updated separately:

| Part | Folder | What it is | How it reaches kiosks |
|---|---|---|---|
| **UI** | [`ui/`](ui/) | The screens: Welcome, Menu, text, prices, styles, receipt layout (React + Vite) | **UI update**: upload a new build to the UI server. Kiosks reload within about 2 minutes. No install. |
| **App** | [`app/`](app/) | The Windows program around the screens: window, full screen, silent receipt printing, auto-start, auto-update (Electron) | **App update**: publish a new installer. Kiosks download and install it by themselves. |

Most changes are UI changes, and they never need a new installer.

## 1. Quick start

**Requirements:** Windows 10/11, Node.js 22, npm 10, Git.

```bash
git clone https://github.com/NuhaNizam/kiosk-test-app.git
cd kiosk-test-app
npm install
npm run electron
```

`npm run electron` starts the UI dev server and opens the kiosk app. Close it with
**Alt+F4**: the screens after Welcome are full screen, with no close button.

Run every `npm` command from the top `kiosk-test-app` folder.

## 3. How it works

```
   DEVELOPER PC                         SERVERS                          KIOSK PC (installed app)
   ────────────                         ───────                          ────────────────────────
   ui/  ── npm run build ──► ui/dist ──► UI server (/ui) ───────────────► screens (reload, no install)

   app/ ── npm run dist ───► release ──► Update server (/updates) ──────► app (downloads + installs .exe)
```

### When the kiosk app opens

1. Windows starts **Self-Service Kiosk** automatically when someone signs in.
2. The app loads the screens from the **UI server** (`UI_URL` in [app/ui.js](app/ui.js)).
   - If the server can't be reached, it shows the copy of the UI built into the
     installer. The kiosk always works, even offline.
3. The app asks the **update server** whether a newer app version exists
   (`build.publish.url` in [app/package.json](app/package.json)).

### Screens and window

- **Welcome** shows in a normal window with a Chrome-style tab strip and address bar.
- **Every other screen** is full-screen kiosk mode, where customers can't leave the app.
- Back to Welcome returns to the normal window.

### "Idle" rule

Updates never interrupt a customer. Both kinds of update wait until the kiosk has
been on the **Welcome screen for 1 minute** ([app/idle.js](app/idle.js)). The one
exception: an app update found as the app opens installs straight away, as long as
nobody has used the kiosk yet.

### The `window.kiosk` API

The app gives the UI these functions ([app/preload.cjs](app/preload.cjs)). They
exist only inside the app, not in a normal browser.

| Function | Purpose |
|---|---|
| `print(page)` | Silent receipt printing (no preview, no dialog) |
| `setFullScreen(on)` | Kiosk full screen on or off |
| `shellVersion` | The installed app version, e.g. `"1.0.6"` |
| `openDevVersion()` | Developer button: open the dev server in the browser |
| `getPrinters()` | List installed printers |

The UI can be newer than the app on a kiosk. Before using a function that older
apps don't have, check that it exists:

```js
if (window.kiosk?.openCashDrawer) window.kiosk.openCashDrawer()
```

- Import with the `@/` alias, e.g. `import { printPage } from '@/features/printing'`.
- Each feature has `components/`, `services/` and an `index.js` that is its public
  API. Import from the feature, not from its inner files.
- Styles use CSS Modules (`*.module.css`).
- Branding and text live in [ui/src/config/kiosk.config.js](ui/src/config/kiosk.config.js).

Run `npm run lint` before committing.

## 6. UI updates

**For:** anything in `ui/`. That covers screens, menu, text, prices, styles and
the receipt layout.

### Steps

1. Change files in `ui/`.
2. Build:
   ```bash
   npm run build
   ```
   Every build gets a new UI version, written into `ui/dist/version.json` and
   into `index.html`. You don't change any version number yourself.
3. Upload `ui/dist/` to the UI server (or let [CI/CD](#12-cicd) do it).

### What the kiosks do

Every minute, each kiosk compares its `version.json` with the server's. When they
differ and the kiosk has been idle on Welcome for 1 minute, it reloads. The new
screens show within about 2 minutes, and nothing is installed.

### Upload rules (real server)

- **Order:** upload `assets/` first, and `index.html` and `version.json` **last**.
  Otherwise a kiosk could load a new page whose files aren't uploaded yet.
- **Keep old `assets/` files.** A kiosk in the middle of an order still uses them.
  File names contain a hash, so old and new files never clash.
- **Caching:** serve `index.html` and `version.json` with `Cache-Control: no-cache`,
  and `assets/*` with a long cache (`max-age=31536000, immutable`).

## 7. App updates

**For:** anything in `app/`. That covers printing, window behaviour, update logic,
Electron version and app dependencies.

### Steps

1. Change files in `app/`.
2. Raise `"version"` in [app/package.json](app/package.json), e.g. `1.0.6` to `1.0.7`.
   Kiosks only ever update to a **higher** version.
3. Build:
   ```bash
   npm run dist
   ```
   This builds the UI first, for the built-in offline copy, then the installer. Output in `release/`:
   - `Self-Service Kiosk Setup 1.0.7.exe`: the installer
   - `Self-Service Kiosk Setup 1.0.7.exe.blockmap`: lets kiosks download only what changed
   - `latest.yml`: tells kiosks the newest version
4. Upload those three files to the update server, **`latest.yml` last** (or let
   [CI/CD](#12-cicd) do it).

### What the kiosks do

Each kiosk checks the update server when the app opens and every 4 hours. It downloads a
new version in the background, then installs it silently and reopens:

- straight away, if nobody has used the kiosk since it opened, or
- after 1 minute idle on the Welcome screen.

### Rolling back

Kiosks never install an older version. To undo a bad release, publish the
previous code again with a **higher** version number (e.g. the 1.0.6 code as 1.0.8).

### Upgrading Electron

Change **both** in [app/package.json](app/package.json):
`devDependencies.electron` (the version to install) and `build.electronVersion`
(the exact version to package). Electron is installed in the shared top-level
`node_modules`, so electron-builder needs the exact version written out.

## 9. Testing updates on one PC

The local servers stand in for the real ones. They serve the build folders directly,
so there is no uploading.

### UI update

1. Terminal 1: `npm run serve-ui` (keep running).
2. Open the installed **Self-Service Kiosk** (or `npm run electron:prod`).
3. Change some text, e.g. the greeting in `ui/src/config/kiosk.config.js`.
4. Terminal 2: `npm run build`.
5. Leave the kiosk on Welcome. The change appears within about 2 minutes.

### App update

1. Install the current version from `release/` (double-click the Setup `.exe`).
2. Raise the version in `app/package.json`, then run `npm run dist`.
3. Terminal 1: `npm run serve-updates` (keep running).
4. Close and reopen the kiosk app. It updates itself. Check **Settings → Apps →
   Self-Service Kiosk** for the new version.

## 10. Setting up a kiosk PC

1. Install the latest `Self-Service Kiosk Setup x.y.z.exe`, by USB or remote access.
   It installs per user with no questions, into `%LOCALAPPDATA%\Programs\kiosk-test-app`.
2. Set the receipt printer as the **Windows default printer**, or set the
   `KIOSK_PRINTER` environment variable to its exact name (see [Printing](#11-printing)).
3. Make Windows sign in automatically to the kiosk user account. The app starts at
   sign-in by itself.
4. Make sure the PC can reach the UI server and the update server.

After this, the kiosk needs no visits: UI and app updates arrive by themselves.

To uninstall: **Settings → Apps → Installed apps → Self-Service Kiosk → Uninstall**.

## 11. Printing

- Receipts print **silently**, with no preview or dialog, through `window.kiosk.print`.
- The UI measures the receipt ([ui/src/features/printing/printLayout.js](ui/src/features/printing/printLayout.js))
  and asks for a page exactly that tall: 72 mm wide with 4 mm margins, and at least
  61 mm tall (the POS-80 driver's minimum). Without this, the receipt prints shrunk
  on a full-length page with blank paper after it.
- **Printer:** the Windows default printer, or the name in the `KIOSK_PRINTER`
  environment variable. A wrong name fails with an error instead of printing elsewhere.
- In a normal browser (`npm run dev`), printing falls back to the browser's print dialog.

## 12. CI/CD

The repository is on GitHub, so CI/CD uses **GitHub Actions**. This section is the
plan. The workflow files are **not in the repository yet**, and the
[prerequisites](#prerequisites) below must be done first.

### Pipeline overview

```
 Pull request ──► CI: lint + build UI + build installer (check only)
                    │
 Merge to main ─────┼──► changed ui/ ?  ──► Deploy UI ──► UI server /ui ──► kiosks reload (~2 min)
                    │
 Tag app-v1.0.7 ────┴──► Release app ──► installer to update server /updates ──► kiosks install
```

| Pipeline | Trigger | Runs on | Result |
|---|---|---|---|
| **CI** | Every pull request and push | Windows | Lint passes, UI builds, installer builds |
| **Deploy UI** | Push to `main` that changes `ui/**` | Ubuntu | New UI live on the UI server |
| **Release app** | Git tag `app-v*` (e.g. `app-v1.0.7`) | Windows | New installer on the update server + a GitHub Release |

Why these triggers:

- **UI** deploys on every merge, because UI updates are safe, fast and frequent.
- **App** releases are deliberate: you raise the version and push a tag. App
  updates replace the program on every kiosk, so they shouldn't happen by accident.
- The installer is built on **Windows**, because the NSIS installer is a Windows build.

### Hosting

One storage bucket with a CDN in front, for example **AWS S3 + CloudFront**:

```
https://kiosk.<env>.delivergate.com/
├── ui/                       ← Deploy UI uploads ui/dist/ here
│   ├── index.html            (no-cache)
│   ├── version.json          (no-cache)
│   └── assets/               (cached for a year; old files kept)
└── updates/                  ← Release app uploads here
    ├── latest.yml            (no-cache, uploaded last)
    ├── Self-Service Kiosk Setup 1.0.7.exe
    └── Self-Service Kiosk Setup 1.0.7.exe.blockmap
```

Use separate **staging** and **production** environments (`kiosk.staging…` and
`kiosk.prod…`), with a test kiosk on staging. Promote to production with a GitHub
Environment that requires approval.

### Prerequisites

1. **Hosting** (bucket + CDN) for staging and production.
2. **Server addresses set at build time.** They are hard-coded to `localhost` today:
   - `UI_URL` in [app/ui.js](app/ui.js): `http://localhost:8081/`.
     The `KIOSK_UI_URL` variable it reads is checked on the kiosk at runtime, not
     at build time, so CI can't set it. It needs to become a build setting, e.g.
     a value passed with `-c.extraMetadata.kioskUiUrl=…` that `ui.js` reads from
     the app's package.json.
   - `build.publish.url` in [app/package.json](app/package.json): `http://localhost:8080/`.
     CI can override it with `electron-builder -c.publish.url=https://…/updates/`.
3. **GitHub secrets / variables:**

   | Name | Purpose |
   |---|---|
   | `AWS_ROLE_ARN` | Role GitHub Actions assumes to upload (OIDC, no stored keys) |
   | `KIOSK_BUCKET` | Bucket name |
   | `CLOUDFRONT_ID` | CDN distribution, to refresh `index.html` / `version.json` / `latest.yml` |
   | `KIOSK_BASE_URL` | e.g. `https://kiosk.prod.delivergate.com` |
   | `CSC_LINK`, `CSC_KEY_PASSWORD` | Optional: code-signing certificate, so Windows SmartScreen doesn't warn |

4. **Remove developer features** first (see the [checklist](#13-going-to-production-checklist)).

### Workflow: CI

`.github/workflows/ci.yml`

```yaml
name: CI
on:
  pull_request:
  push:
    branches: [main]

jobs:
  check:
    runs-on: windows-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 2      # what-changed compares with the previous commit
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
      - run: npm ci
      - run: npm run lint
      - run: npm run build                     # UI builds
      - run: npx electron-builder --win --publish never   # installer builds (not uploaded)
        working-directory: app
      - run: npm run what-changed -- --last-commit
```

### Workflow: Deploy UI

`.github/workflows/deploy-ui.yml`

```yaml
name: Deploy UI
on:
  push:
    branches: [main]
    paths: ['ui/**']
  workflow_dispatch:

permissions:
  id-token: write   # AWS login without stored keys
  contents: read

jobs:
  deploy:
    runs-on: ubuntu-latest
    environment: production        # add required reviewers in GitHub settings
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
      - run: npm ci --workspace ui --include-workspace-root
      - run: npm run build

      - uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: ${{ secrets.AWS_ROLE_ARN }}
          aws-region: ap-south-1

      # 1. Assets first, cached for a year. No --delete: old files stay for
      #    kiosks still showing the previous UI.
      - run: >
          aws s3 sync ui/dist/assets s3://${{ secrets.KIOSK_BUCKET }}/ui/assets
          --cache-control "public,max-age=31536000,immutable"
      # 2. Then everything else; index.html and version.json never cached.
      - run: >
          aws s3 cp ui/dist s3://${{ secrets.KIOSK_BUCKET }}/ui/ --recursive
          --exclude "assets/*" --cache-control "no-cache"
      - run: >
          aws cloudfront create-invalidation --distribution-id ${{ secrets.CLOUDFRONT_ID }}
          --paths "/ui/index.html" "/ui/version.json"
```

### Workflow: Release app

`.github/workflows/release-app.yml`

```yaml
name: Release app
on:
  push:
    tags: ['app-v*']          # e.g. app-v1.0.7

permissions:
  id-token: write
  contents: write            # to create the GitHub Release

jobs:
  release:
    runs-on: windows-latest
    environment: production
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
      - run: npm ci

      # The tag must match app/package.json, so the installer has the right version.
      - shell: bash
        run: |
          VERSION=$(node -p "require('./app/package.json').version")
          [ "app-v$VERSION" = "$GITHUB_REF_NAME" ] || { echo "Tag $GITHUB_REF_NAME != app-v$VERSION"; exit 1; }

      - run: npm run build
      - run: npx electron-builder --win --publish never -c.publish.url=${{ secrets.KIOSK_BASE_URL }}/updates/
        working-directory: app
        env:
          CSC_LINK: ${{ secrets.CSC_LINK }}
          CSC_KEY_PASSWORD: ${{ secrets.CSC_KEY_PASSWORD }}

      - uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: ${{ secrets.AWS_ROLE_ARN }}
          aws-region: ap-south-1

      # Installer + blockmap first, latest.yml LAST: it is what tells kiosks
      # the new version exists.
      - shell: bash
        run: |
          aws s3 cp release/ s3://${{ secrets.KIOSK_BUCKET }}/updates/ --recursive \
            --exclude "*" --include "*.exe" --include "*.blockmap"
          aws s3 cp release/latest.yml s3://${{ secrets.KIOSK_BUCKET }}/updates/latest.yml \
            --cache-control "no-cache"
          aws cloudfront create-invalidation --distribution-id ${{ secrets.CLOUDFRONT_ID }} \
            --paths "/updates/latest.yml"

      # Keep a copy of every installer on GitHub.
      - uses: softprops/action-gh-release@v2
        with:
          files: |
            release/*.exe
            release/*.blockmap
            release/latest.yml
```

### Releasing with CI/CD

**UI change:** open a pull request, CI passes, merge to `main`. Deploy UI runs, and
kiosks show the change within about 2 minutes.

**App change:**

```bash
# 1. Raise "version" in app/package.json (e.g. 1.0.7), commit, merge to main
# 2. Tag and push:
git tag app-v1.0.7
git push origin app-v1.0.7
```

Release app runs, and kiosks install it at their next start or idle period.

**Both:** release the app first, then merge the UI change.

## 14. Troubleshooting

| Problem | Cause and fix |
|---|---|
| `npm run electron` fails with *"does not provide an export named BrowserWindow"* | VS Code's terminal sets `ELECTRON_RUN_AS_NODE=1`. The npm scripts remove it; if you start Electron another way, clear that variable first. |
| Electron hangs or "electron.exe not found" after `npm install` | The Electron download failed silently. Run `node node_modules/electron/install.js`. |
| `npm run dist`: *"Electron version … is a range"* | `build.electronVersion` is missing in `app/package.json`. Set it to the installed version. |
| A second kiosk window won't open | Only one instance can run (single-instance lock). Close the first (Alt+F4). |
| The kiosk shows old screens | The UI server wasn't reachable when it opened, so it shows the built-in copy. Start the UI server; the kiosk switches to it when idle on Welcome. |
| A UI update doesn't appear | It waits for 1 minute idle on **Welcome**. Return to Welcome and wait about 2 minutes. Check that `npm run build` finished. |
| An app update isn't installed | The version in `app/package.json` wasn't raised before `npm run dist`, or the update server isn't reachable. Check the server log for `GET /latest.yml`. |
| Receipt prints small with lots of blank paper | The page size isn't reaching the printer. Print through `window.kiosk.print` (the app), not `window.print()`. |
| *"Couldn't open the developer version … dev server is not running"* | Expected in the installed app. Start `npm run dev` first, or remove the button for production. |
| VS Code: *"No inputs were found in config file …/jsconfig.json"* | A stale tab of the old top-level `jsconfig.json`. Close it without saving, then run **TypeScript: Restart TS Server**. The real one is `ui/jsconfig.json`. |
| Port 8080, 8081 or 5173 already in use | A server is still running in another terminal. Close it, or use that one. |
| Testing `release/win-unpacked` added a startup entry | Running the packaged app registers "start with Windows". Remove `electron.app.Self-Service Kiosk` under `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`. |
